# ADR-0030: Research conventions (Phase 7)

Status: Accepted, 2026-11-22. Changes no Part A invariant. Every choice below is reversible.

## Decisions
1. **Layout.** `arthashreni.research` is pure (no database, network or web framework; import-linter contract). `research_store.py` is the database layer (like `portfolio` and `review`), `cli_research.py` the CLI. Migration 0006 adds `fund_holdings`, `news_events`, `ipo_research`, `ipo_classifications`, `research_claims` to both dataset schemas (DEMO and REAL stay apart, A3.8).
2. **Fund and ETF holdings arrive as one documented CSV** (`isin,name,pct_to_nav`, cash and other lines included). AMC disclosure layouts differ and their terms are unchecked (V35), so there is no scraper and no per-AMC parser yet: `holdings import FUND FILE --as-of DATE`. A file is accepted whole or rejected whole: bad ISIN, negative or over-100 weight, duplicate line, or a total outside 100% +/- 1 point rejects everything (D3). Rows are bitemporal and append-only: a corrected file for the same date is a new file; reads take the newest disclosure date, then the newest file known at `known_at` (E4). The same file twice is refused.
3. **Look-through and overlap** reuse the Phase 4 pure functions. `build_report` now loads stored files; funds without one are still listed as "no holdings data" and overlap stays `missing`. A file older than the latest month end that must be public (month end minus 10 days, the SEBI monthly-disclosure lag, V35) is `stale`, and the exposure computed from it is `stale`. `holdings overlap` prints `[stale]` with the reason when either fund's file is stale. Underlyings are keyed by ISIN (name when a line has none, such as cash); direct holdings are keyed by ISIN too, so a stock held directly and through a fund merges. Lines without an ISIN do not merge with direct holdings: exposure is understated, never invented.
4. **News** comes from RSS/Atom files you save from official feeds (`news import FILE --feed NAME`). No fetcher exists: feed terms are unchecked (V36) and D1 allows manual import when no compliant source is verified. Content is untrusted data (invariant 11): `defusedxml` (no entity expansion), tags stripped, lengths capped, links must be http(s), items without a title, usable link or a date with a zone are rejected and counted. **De-duplication:** the same normalised headline on the same IST day is one event, whichever feed carried it; the event keeps its first link and lists every feed. A reworded headline about the same news is a different event (known limit; fuzzy matching is not built).
5. **IPO research.** The system never decides that an IPO is allowed. The investor records six checklist facts read from the RHP, each with a source document (`ipo-research fact`; `min_lot_value` also sets the IPO's minimum application, never a hardcoded number), then classifies it (`ipo-research classify`) with a reason. `ALLOWED` is refused unless the IPO is mainboard, still PLANNED and the checklist is complete; `NOT_ALLOWED` is always possible. The Phase 5 `ipo_verdict` is unchanged, so "can apply" still also needs the sinking fund to cover the minimum, and SME IPOs stay excluded. The checklist is this project's own minimum, not a regulatory list. Recording any new fact for an ALLOWED, still-PLANNED IPO resets it to UNRATED (the ALLOWED row stays in `ipo_classifications`), so a classification is never older than the facts it rests on.
6. **Claims** (`research_claims`) are statements that point at stored evidence (NEWS, IPO_FACT, FUNDAMENTAL, HOLDINGS id); a claim whose evidence does not exist is refused (invariant 6). They give Phase 8 the evidence IDs the LLM must cite.
7. **Fundamental ratios** (`research/fundamentals.py`: growth, margin) are pure `Measured` functions over SEC values that Phase 3 already stores. They are not yet wired into a report.

## Not built (named, not hidden)
Commodity drivers; per-AMC disclosure parsers and any holdings or news fetcher; US ETF issuer holdings files; fuzzy news de-duplication; linking news to held assets; UI pages for research (the Phase 6 UI is unchanged); macro feeds (V34).

## Consequences
Look-through and overlap are real once you import files; until then nothing changes. Import-linter now also keeps `research` out of the ledger, DQ, analytics, policy and risk packages. New dependency: `defusedxml` (PSF licence, already in the lock file as a transitive dependency); dev: `types-defusedxml`.
