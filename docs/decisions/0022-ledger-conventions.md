# ADR-0022: Ledger conventions (Phase 2)

Status: Accepted, 2026-11-11. Fills gaps in C1/C2; changes no Part A invariant.

## Decisions
1. **Sign of net cash.** Seen from the account's cash: money leaving the account is negative (BUY, SIP, FEE, TAX, WITHDRAWAL, IPO_APPLICATION, IPO_BLOCK, IPO_ALLOTMENT), money arriving is positive (SELL, REDEMPTION, DIVIDEND, INTEREST, DEPOSIT, IPO_REFUND). Quantities, prices, fees, taxes and stamp duty are never negative; direction comes from the type. `NewTxn` rejects a wrong sign. `FX_CONVERSION` may have either sign.
2. **Derived cash.** BUY/SIP/SELL/REDEMPTION may omit net cash; it is derived as `-(qty x price + fees + taxes + stamp)` or `qty x price - fees - taxes - stamp`. Unit moves with no external cash (DIVIDEND_REINVESTMENT, SWITCH_IN/OUT, TRANSFER_IN/OUT) default to 0. Every other type must state its net cash.
3. **Cost basis.** A lot costs `qty x price + fees + stamp_duty` (x FX for foreign assets). `taxes` are stored but not added to cost; whether any of them belong in cost is a tax-phase decision [VERIFY]. Disposal proceeds are `(qty x price - fees - stamp_duty) x FX`, split across consumed lots by quantity with the last lot taking the remainder, so totals stay exact.
4. **Corrections.** A CORRECTION row carries the corrected values in full plus `corrected_type` (the real economic type) and `supersedes_id`; one correction per row (partial unique index); a correction of a correction is allowed. A void is a correction with zero quantity and zero cash; it drops out of `transactions_effective`. `load_audit` returns every physical row.
5. **Reserved types.** SPLIT, BONUS, MERGER and CORPORATE_ACTION cannot be imported as transactions. Unit changes from corporate actions come only from the `corporate_actions` table (one source, no double counting). `DEMERGER` is not supported and not in the table's CHECK.
6. **Bonus.** Amends ADR-0006: a bonus creates a new lot with zero cost dated at the ex-date (approximating the allotment date) and whole units only (`floor`). It is not treated like a split. Split multiplies units and keeps cost. Merger moves lots to the successor keeping cost and acquisition date. Entitlement is computed on holdings at the ex-date, not the record date [VERIFY in the tax phase].
7. **Event order within a day:** corporate actions, then acquisitions, then disposals, then row id. A sale recorded before a same-day buy is therefore valid.
8. **IPO.** Four separate events: IPO_APPLICATION (intent, cash 0), IPO_BLOCK (the ASBA hold, negative cash), IPO_ALLOTMENT (units; cash 0 because the block pays for it), IPO_REFUND (release of the unallotted part, positive cash). Net cash over the sequence equals the cost of the allotted units.
9. **FX_CONVERSION** is an internal swap: `net_cash_orig` is the amount received, `net_cash_inr` is 0 (the external INR flow is the DEPOSIT), `fx_rate` is the broker's rate.
10. **Assets** are looked up by ISIN, `AMFI:<code>` or `TICKER:<MIC>:<symbol>`. `ref.assets.is_demo` separates the datasets: DEMO sees only DEMO assets, REAL only real ones. DEMO assets use synthetic identifiers (`ZZ...`). SME assets are refused at creation (ADR-0021).
11. **Duplicates.** Fingerprint = SHA-256 of (item kind, source, account, asset reference, type, date, quantity, price, net cash, external id, occurrence number within the file). Identical trades in one file stay distinct; the same file or an overlapping one maps to the same fingerprints. The same trade imported from two different sources is not detected as a duplicate (use one source per account); reconciliation shows the excess.
12. **Import safety.** The same file bytes are refused once imported (a REJECTED batch frees them). Preview stores raw row and candidate, immutable. Commit refuses a batch with blocking problems, and refuses rejected/ambiguous rows unless `--accept-skipped`. Blocking: a sale that would make a holding negative (checked at preview and again at commit), CAS `UNITS_MISMATCH`, CAS closing balance different from the recomputed one, any casparser warning.
13. **CAS units (C6).** For purchases and redemptions, `|units x NAV - amount|` (amount net of that day's stamp duty on purchases) must be within half a unit-rounding step of NAV plus ₹0.01. Stamp-duty lines are folded into the same day's purchases pro rata. Unmapped CAS entry types (switch mergers aside) are AMBIGUOUS and need manual handling.
14. **Account labels from CAS** are masked: `FOLIO-` or `DEMAT-` plus the identifier with all but the last four characters replaced by `*`. Accounts are never created automatically.
15. **Reconciliation** compares units as of the statement date, rounded to 3 decimals for mutual funds and 6 otherwise. Only the latest statement per (account, asset) can block. An accepted difference stays accepted only while the difference is unchanged.
16. **Inbox watcher** is a polling loop (`import watch`) over `data/imports/inbox/`; Phase 3 schedules the same scan. Sub-folder name = account label for sources that do not name one.
